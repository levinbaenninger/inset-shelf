# Inset Shelf

Inset Shelf is a small side window that docks next to the window you are working in and keeps what you want to come back to. You can save selected text from any app, drag over part of the screen, pin a spot, draw a sketch, attach files, or write a note or a prompt for later. Each item remembers the app, window and web page it came from. It can be checked off, copied back into another app, or dragged out.

It is the third Inset prototype. [Inset Context Pin](https://github.com/levinbaenninger/inset-pin) tests one pinned thought per capture in a popover. Inset Shelf tests a running list that you build up while you work.

[IMPLEMENTATION_REPORT.md](IMPLEMENTATION_REPORT.md) lists what was tested, on which system, and what is still open.

## Install a test build

Install once, then the app updates itself. Download a build from the [Releases page](https://github.com/levinbaenninger/inset-shelf/releases). The **Preview build** release holds the latest commit on `main`. Each pull request also uploads builds as workflow artifacts on its CI run.

The builds are not signed with a developer certificate, so each system warns once, at the first install.

### macOS

1. Download `inset-shelf-<version>-mac-arm64.dmg` for Apple silicon, or `-mac-x64.dmg` for an Intel Mac.
2. Open the disk image and drag **Inset Shelf** to **Applications**.
3. Open the app. macOS blocks it the first time. Open **System Settings > Privacy & Security** and click **Open Anyway**. If you prefer the terminal, run `xattr -dr com.apple.quarantine "/Applications/Inset Shelf.app"` and open the app again.
4. The first time it opens, a small setup window asks for the permissions. It has three pages: **Welcome**, **Allow access** and **Done**. Every page after Welcome has **Back**, `→` and `←` move between them, and **Not now** skips one. The app works without the permissions you skip.
   - **Accessibility** (**Device Control and Data Access** from macOS 27), for double Shift and for a browser page's address. **Allow** shows macOS's prompt and opens the right settings page, and the window moves to the edge of the screen, beside it. Turn on **Inset Shelf** there. The row turns green within a second, and double Shift starts listening without a restart.
   - **Screen & System Audio Recording**, for the title of the window an item came from and for window links. **Allow** works the same way. macOS applies this one only after the app opens again, so the row then offers **Reopen to finish**, and the app comes back on **Allow access**.
   - If **Inset Shelf** isn't in the list, drag the **Inset Shelf** tile from the setup window into it.
   - **Done** hands over to the shelf: **Start Using Inset Shelf**, or **Show Me Around** for a short walkthrough of it (see [Getting started](#getting-started)).
   - **Set Up Permissions…** in the **Inset Shelf** menu and the menu bar icon's menu opens the window at **Allow access**. **Turn On…** in the shelf's **Double Shift is off** banner and **Set Up Screen Recording…** in the window-link picker do too, with their permission picked out.
   - **Automation**, once per browser, the first time an item is saved from Safari, Chrome, Edge, Brave, Arc or another Chromium browser. It lets the app read the address of the page in front. The setup doesn't ask for it. Firefox, Zen and apps built on web views are read through Accessibility instead and don't ask.

   An install that ran before the setup existed doesn't show it by itself. Screenshot cards start once the setup is done or skipped, so macOS's Desktop and Documents folder prompts don't come first.

The app has a Dock icon, a menu bar and the Shelf mark (a rounded frame with a list in its open corner) in the menu bar's status area. **Settings…** (`⌘,`) can hide either icon.

### Updates

The app checks the **Preview build** release when it starts and every four hours, and downloads a newer build in the background. When the download is ready, it says so once, and the menu bar icon's menu and the **Inset Shelf** menu offer **Restart to Update to v…**. If you don't restart, the update installs when you quit. The menu bar icon's menu always shows the running version and **Check for Updates…**.

On macOS every build is signed with the same self-signed certificate, so the update keeps your permissions and macOS checks that the new build comes from the same signer. A build that shows version 0.1.0 has an ad-hoc signature that can't accept a signed update. Install the current build by hand once, as above, and grant the permissions again. After that it updates itself.

On Windows only the installer (`.exe`) updates itself. The portable `.zip` copies can't. To update one, download the new zip.

### Windows

1. Download `inset-shelf-<version>-win-x64.exe` for the installer, or `-win-x64.zip` to run it without installing. Use `-win-arm64.zip` on an Arm device.
2. If SmartScreen shows **Windows protected your PC**, click **More info**, then **Run anyway**.
3. Look for the Shelf mark (a rounded frame with a list in its open corner) in the notification area of the taskbar. Windows may put it behind the **^** (Show hidden icons) arrow; drag it onto the taskbar to keep it in view. Click it to show or hide the shelf, and right-click it for its menu. Starting the app again from Start shows the shelf.

The Windows build has been run on Windows 11; [IMPLEMENTATION_REPORT.md](IMPLEMENTATION_REPORT.md) lists what was checked. The keys added in the feedback round (`Ctrl+Shift+N` with a note field focused, `Ctrl+Shift+L`, `Ctrl+Alt+C` and the field keys) have not been tried on Windows yet. On Windows the shortcuts use `Ctrl` where the Mac uses `⌘`, and there is no menu bar: **Settings…** is in the tray icon's menu, in the shelf's top **⋯** menu and on `Ctrl+,`, and that **⋯** menu also holds **Float on Top** and **Inset Shelf Help**. Double Shift copies the selection with `Ctrl+Insert`, not `Ctrl+C`, which would stop a running program in a terminal.

## Use it

| Keys | What happens |
| --- | --- |
| `⇧ ⇧` (tap Shift twice) with text selected | Saves the selection, with the app, window and page it came from, and the links inside it. When the shelf is hidden, a short notice beside the pointer confirms it once it is saved to disk, or says why it wasn't. Your clipboard is put back as it was. |
| `⇧ ⇧` again while that notice shows | Turns the notice into a one-line field: say why the capture matters and press `Return`, and it goes into the item's description without the shelf opening. **Why** at the end of the notice does the same with the mouse. `Esc` throws the words away, and clicking elsewhere keeps what you typed. A capture you don't add a why to works as before, and other selected text is a new capture. When the field can't get the keyboard, the shelf opens at the item's description instead. |
| `⇧ ⇧` with nothing selected | Shows or hides the shelf. |
| `⌃⌥S` (`Ctrl+Alt+S` on Windows) | Shows the shelf, or hides it when it is already in front. |

The shelf opens beside the window in front, centred on its height and up to 620 points tall. When there is no room beside it, it opens inside the window's right edge. Without a window it opens at the right of the screen, centred. It floats above other windows, on every Space and over full-screen apps, until you hide it with `Esc`, the **×** at the top or the shortcut. However you hid it, it opens again with the caret in the note field, unless you were editing an item, had details open or had words in the search. A drawing or the picker closing over the open shelf leaves the keyboard where it was.

Inside the shelf (an empty shelf lists the ways to start):

- Jot down a note or a prompt and press `Return`. Notes are Markdown, formatted as you type: `**bold**`, `*italic*`, `` `code` ``, `- ` or `1. ` lists, `> ` quotes and links turn into their formatting at once, and pasted formatting is kept. `⇧↩` starts a new line or list item (twice leaves a list), and `⌘↩` adds the note too. Notes are still stored as Markdown, and links in them open in the browser. A single line starting with `# ` makes a section: it stays plain text, and a chip at the end of the field says **↩ New section ‘Name’** (or **Go to section** when it exists). A long name puts the chip on its own line under the field, so the note keeps its width. The **+** in the note field adds files as new items, opens a new drawing or a new window link. Drop files on the shelf, or paste a picture or file with `⌘V`, and each becomes a new item; drop them on an item instead to attach them to it (see **Attachments**).
- The list shows every section as a group, empty ones too; the empty section new items go to says so in one faint line. Click a section's name to fold it away; point at it to read a name too long to show. Once there is more than one section, a filled dot at the right of a section's name shows where new items go. Point at another section's name and click the ring that appears there to send new items to it. A section's **⋯**, or a right-click on its name, renames it, clears its checked items or deletes it; both ask first when items would be deleted. **New Section** in the **⋯** at the top (or a right-click on empty space), or `# Name` and `Return` in the note field, makes a section. The **View** menu and `⌘1` to `⌘9` also pick the section for new items.
- Drag an item onto another section to move it there. Dragging a text item into another app drops its words; dragging an image or file out drops the file.
- The search field (`⌘F`) narrows the list by text, title, note, description, steps, pin labels, file name, attachment names, app, window title or address, and marks the words it found. `due:today`, `due:overdue`, `due:week` (overdue included), `due:any` and `due:none` filter by Due; the filter button at the end of the field picks them for you, and while you type `due:` the shelf lists the filters with what each one means (`Return` takes the first). `from:here` keeps only the open items from the window the shelf opened beside (see **Recall** below).
- Long items show two lines; select one to read all of it, with the links it holds. The line under an item says where it came from: a GitHub pull request or issue, a ChatGPT or Claude chat, a post on X or a YouTube video by name, other pages by their site and title. Click it (or press `⌘O`) to open the page, or the desktop app it came from: a ChatGPT thread, a Claude chat or project and a Notion page open right where they were; Figma, Slack and Linear come to the front. ChatGPT threads are found by their title in `~/.codex/session_index.jsonl`. On Windows, the page of a selection copied from Chrome, Edge, Firefox or an app built on Chromium is the one the browser noted with the copy, and a desktop app opens only at a chat or page it has a link for (a Claude chat, a Notion page); other items open their page.
- **Details.** Every item can also hold a **Description**, **Next steps** (a checklist), a **Due** date, **linked windows** and **attachments**; images and files can have a **Title**, which shows in place of the caption (the note copied with them). None of it is asked for when you capture. Up to three small badges on the item's source line show the Due chip (**Overdue** in red, blue when due today, else the day; point at it for the date; dates follow your system's language), step progress, linked windows and pins. The Due chip always shows whole: in a narrow shelf the source and the other badges give way first. Point at a source, file name or label that ends in **…** to read all of it. A file whose name would be cut short puts its badges on a line of their own. Selecting an item shows its words and caption up to ten lines, a title and its description up to three, and its picture at most 12rem tall; **Show more** under the words shows the rest in place. It also shows its pin labels, steps you can tick and its windows as one row of small pictures (click one to reopen it; **+3** opens details with the rest). A long list of pins or steps shows its first few, and a line such as **27 more pins · 15 more steps** opens details with all of them. A link in it shows its site under its words when both don't fit on one line. `→` (or **Details** in the open item) opens the details view: everything about the item, with one **Add** menu for the fields it doesn't have yet, and when it was added at the foot. `⌘D` adds or focuses the description, `⇧⌘S` the next steps (also inside a note: it no longer strikes text through, `~~text~~` still does) and `⇧⌘D` the Due picker (Today, Tomorrow, This weekend, Next week, Pick a date…, Clear), from the list too. **Pick a date…** opens a calendar: the arrow keys move the day, `Return` picks it and `Esc` closes it. The × in the chip clears it. In a step, `Return` adds the next one and `⌫` in an empty one removes it; Click a linked window's description (or **+ Description**) to edit it; `Return` keeps it and `Esc` puts back what it said. `⌘Z` puts back a removed step, window or attachment, or a pin's label as it was before you last edited it. `←`, the back button or `Esc` returns to the list where you left it. Edits save as you type.
- **Window links.** **File > New Window Link…** (`⇧⌘L`, or **+** in the note field) opens a picker with the open windows; pick some, in order, and they become a note named after them, which you can retitle at once. **Link Window…** in details adds windows to any item. Each window keeps its picture, app, page or file and an optional description; **Open page**, **Open file** or **Bring app forward** (**Open app** on Windows) reopens it, and **Reopen all** reopens every one. In details a window's name takes the whole row; its open button and **⋯** show when you point at it or `Tab` to them. macOS needs Screen Recording for the picker.
- **Attachments.** Any item can hold up to 12 screenshots, pictures, files and drawings besides its own words, picture or file. Drop files on an item to attach them: the item lights up under the pointer, and a notice says how many landed and offers **Undo**. A full item refuses the drop and says why; nothing becomes a new item instead. In details, **Add** lists **Attach Files…**, **Paste Image** and **New Drawing…**, and `⌘V` attaches a picture or file from the clipboard (in the list `⌘V` still adds a new item). With 12, those entries are off and say so. A screenshot card can attach its screenshot to the selected item (see **Screenshots**). An item shows its first three as small tiles under its words, and **+9** for the rest, which opens details. A click on a tile selects the item, a double-click opens a picture in the drawing window, and `⌫` deletes the item as anywhere on it. Details show all of them, with **3/12** beside the name: click a picture to draw on it, drag any one into another app as a file, and remove one with `⌫` or its **×**, which shows when you point at it or `Tab` to it. **Undo** or `⌘Z` puts it back. Point at a tile for its whole name. An attached picture takes pins and marks as an image item does: pick its tile and its pin labels show under the tiles, to type in, with **Move pins** to place them in the drawing window. A picture whose file was deleted outside the app shows as missing. An item without attachments looks exactly as before. The shelf file is upgraded to hold them the first time the shelf changes; an older build then can't read it, sets it aside as `shelf.unreadable-<time>.json` and starts empty, and every picture and file stays in the data folder.
- Each item's **⋯** button, or a right-click, opens its menu: **Copy**, **Copy with Details** (`⌥⌘C`, when it has a link or details), **Copy with Link**, **Details**, **Annotate** for an image or **Open Page** / **Open in …** for the rest, **Edit**, **Check Off**, **Move to**, the colours and **Delete**. While the menu is open, the keys it shows (`⌘C`, `⌥⌘C`, `⌘O`, `→`, `⌫`, and `⇧⌘C` for several picked items) act on the item you right-clicked, whichever entry is highlighted. `↑` and `↓` move the highlight, `Return` or `Space` choose the highlighted entry (on the **Move to** list too, which `→` opens), and other shortcuts, the menu bar's included, do nothing until the menu closes. When the menu closes, focus goes back to that item. Deleting an item doesn't ask: a notice with **Undo** appears for each one, and `⌘Z` brings back the last. The last ten deletions can be undone. A colour shows as a bar along the item's left edge. Images and files take a note under them; selecting one shows it large.
- Double-click an image to see it large. Draw on it with the drawing tools and **Save** to replace it on the shelf. The **Pin** tool (`P`) places numbered map pins: click to drop pin 1, 2, 3…, drag one to move it, `1`–`9` select one, the arrow keys nudge it (`⇧` for 10 px; one `⌘Z` undoes a held key), `⌫` removes it and the rest renumber, and `⇧P` drops one at the pointer. Moving focus to the toolbar lets go of the selected pin. Pins stay editable beside the image; their labels are set in details. The pen moved to `B`.
- Edit an item where it is: click the words of a selected item (or double-click a closed item's words) and the caret lands where you clicked, with nothing around the words changing. A click on a link opens it instead. The words show a light tint while you type, and the pointer turns to a text caret over words you can edit. The note under a selected image or file edits the same way; one without a note shows **Add a note…**, which starts it. In details, one click on the item's words edits them at that word too, and the title, caption, description and pin labels read as text, wrap when long and show a light tint when you point at them or type. Edits save as you type; `Return` or clicking elsewhere ends the edit and `⇧↩` adds a line. `Esc` puts back what an item said; in a note it keeps what you typed and hides the shelf.
- `↑` and `↓` move through the items. `Space` checks one off, `Return` edits it (or an image's or file's note) with the caret at the end, `⌘C` copies it, `⌥⌘C` copies it with its link and details (as in every Inset app), `⌘O` opens it (an image to draw on, anything else where it came from), `⌥⌘↑` and `⌥⌘↓` move it to the section above or below, and `⌫` deletes it (only from the item itself, its picture or an attachment's tile, not from a step's checkbox, a window or another button in it). `⌘Z` brings back the last deleted item. The **Item** menu in the menu bar lists these keys. `Esc` hides the shelf; while you type a note, a search or an edit, the first `Esc` clears or ends it. A note under an image or file saves as you type, so `Esc` there hides the shelf at once.
- `⌘`-click picks several items and `⇧`-click a range; `⌘A` picks every item shown, and `Esc` lets go. **Copy as List** (`⇧⌘C`, or `⌘C` with several picked) copies them as a numbered list with their links. The first image goes inside the list's formatting, so apps that paste formatting (Teams, Outlook) show the picture with the words, and apps that paste plain text (T3 Code, a terminal) get the words. A list of images alone copies the first image. With nothing picked it copies the open items of the current section. `Space`, `⌫`, **Move to** and dragging act on all picked items.
- Short notices confirm what you can't see happen: files added, items moved, lists copied, checked items cleared.
- When more than one banner waits at the top of the shelf (Double Shift off, not saved, a failed capture), only the newest is open and the others fold to one line each; click one to open it. **Show full message** shows a long reason in full, from the keyboard too.
- Copying a saved selection puts it back as the app copied it, so its links and formatting paste too. Copying an image puts the image, with its pins drawn in, and its note on the clipboard. **Copy with Link**, **Copy with Details** and **Copy as List** add the description, the steps as a `- [ ]` checklist, `Due:` and the linked windows when an item has them; an item without them copies exactly as before. Copying a file puts the file itself on the clipboard. **Copy with Details** and **Copy as List** name each item's attachments, and in apps that paste formatting they show its pictures too; **Copy** and **Copy with Link** leave attachments out. Every copy of shelf items first saves an edit you are still typing, waits until the shelf is saved to disk, and then copies the items as they were when you copied: words typed during that wait are not copied. Words you type into an item reach the app as you type, so nothing waits for you to leave the field. When the shelf can't be saved, the **Not saved to disk** notice says why in plain words (for example "The disk is full."), and each item whose changes aren't on disk says **Not saved** on its row and in its details, with **Retry** and **Discard changes**. Discard changes puts back only that item as it was last saved, without writing anything: a save still on its way is dropped, or the shelf file from before it (`shelf.json.prev`) is renamed back, so it works on a full disk too. A new capture that was never saved offers **Delete** instead. Copying an item that isn't saved copies nothing and offers **Retry**; once Retry has saved it, copy again. A copy whose changes you discard while it waits copies nothing either. Retry and copies give up after 3 seconds if the disk doesn't answer, and say so. Quitting, or restarting to update, first waits up to 3 seconds for the shelf, an edit you are still typing, and a drawing with marks. When something still isn't saved, the app stays open and the shelf asks, with the reason in plain words (the drawing's too): **Retry** saves it (the drawing too) and then quits, **Quit without saving** quits without it, and **Cancel** keeps the app running with the drawing open as it was. A drawing saved by Retry stays open until the shelf file holds it, and Retry never adds it twice. While the quit waits or asks, the drawing window is locked, and so is the drawing while its own save is on its way. Return always means Retry, Esc means Cancel, and Space presses the button that has focus. If the shelf window doesn't answer in time while it holds an edit, or it crashed or reloaded holding one, a system dialog asks instead: **Wait**, **Quit anyway** or **Cancel**. The same dialog takes over, with the same number of changes, when the shelf window crashes, reloads or stops answering while it asks. The screenshot card's **Copy** and a new drawing's **Copy and Save** carry their own picture, so they copy even then; the drawing says if it could not be saved. When the shelf file couldn't be opened at launch, nothing is saved that session (a notice says so) and copies work as usual. Drag an image or a file out of the shelf to drop it into another app.

**Screenshots**: take one as usual, and a card with it appears beside the shelf. On macOS that is a screenshot to the clipboard or to a file. On Windows it is one that Snipping Tool (`Win+Shift+S`, or `PrtScn`) or `Win+PrtScn` saves to the Screenshots folder, which Snipping Tool does unless **Automatically save screenshots** is off; a screenshot that only goes to the clipboard (`Alt+PrtScn`) shows no card. **Add to Shelf** shows on the card at once and is the first control `Tab` reaches. Hover the card, or `Tab` onto it, for **Copy** beside it and the corners, which dismiss it, keep it on screen, annotate it or save it to Downloads. When the shelf is open with an item selected or in its details, or an item was made in the last 2 minutes, a second small button, **Add to “First words…”**, attaches the screenshot to that item instead; it is not there otherwise, or when the item already holds 12. While either button saves, it reads **Saving…** and the card stays. The card goes once the screenshot is saved. When saving fails, the card stays with all its buttons in view, says why in two lines under the picture (`Tab` to the message to read all of it), and offers **Retry** on the button you pressed. Retry adds the screenshot again if its new item was deleted meanwhile, and says so when the item it was to go to is gone. Drag it into another app to drop it as a file. Unless kept, it goes away on its own after a few seconds, but not while the pointer or the keyboard is on it. **Settings** turns the cards off. Screenshots saved to a file show once macOS has written them, which is after its own floating thumbnail is gone.

**Recall**: when you come back to a window, page or repo that open items came from, a small pill in that window's bottom-right corner says **3 items from here**. Click it to open the shelf with only those items; the search then says `from:here`, and clearing it shows everything again. The pill never takes the keyboard, a key you press hides it, and it goes on its own after a few seconds.

- It shows once per visit, and only when the place was away for 10 minutes. After a pill you leave alone it waits an hour, then four hours. Two pills are never less than 2 minutes apart.
- Its **×** keeps that place quiet, and so do three pills you leave alone, until the items from it change.
- A web page matches by its address: a GitHub pull request with all its tabs, every other page of a repository together, a ChatGPT or Claude chat in the browser or the Claude app. A ChatGPT, Claude or T3 Code thread in its desktop app matches by its link. In VS Code and Cursor, every file of the same project matches. Other apps match by the same window title. An app alone never matches, and checked-off items don't count.
- The shelf, opened beside such a window, shows a mark with the count in its search field. Click it to filter the same way, with the pill turned off too.
- **Settings > Recall** turns the pill off.
- On macOS it needs Screen Recording for window titles or Accessibility for page addresses, which captures use already. It asks for no new permission. It reads a browser's address only when an open item came from a page in that browser, so the Automation prompt shows only for a browser you already captured from. What it saw stays in memory until the app quits, and nothing is sent anywhere. On Windows, pages match by their title.

**File > New Drawing…** (`⌥⌘N`, or **+** in the note field) opens a drawing window with pen, line, arrow, rectangle, ellipse and text tools. The tick at the end of its toolbar (**Save**, `⌘↩`) adds the drawing to the shelf, on a dark page in the dark theme and a white one in the light theme. The copy button before it (**Copy and Save**) also puts it on the clipboard. While a drawing has unsaved marks, **New Drawing…** and opening another image bring it to the front instead of replacing it, and it says so. Closing it with marks asks first, and says whether the shelf already has the drawing. When a save fails, the reason shows under the title, across the window. A line of text longer than the window scrolls inside its field, which fades at the end that hides words.

**Keyboard Shortcuts** (`⌘/`, `Ctrl+/` on Windows, or **Help**, the tray menu or **⋯**) lists every key for your system.

**Settings…** (`⌘,`, or **⋯** at the top of the shelf) turns on Open at Login, chooses whether the app's icon shows in the Dock, the menu bar or both (macOS only), turns recall's pill off, and can mark items as done when they are copied.

The shelf is stored in one file, `shelf.json`, with images and files in an `attachments` folder and the settings in `settings.json` next to it:

- macOS: `~/Library/Application Support/Inset Shelf`
- Windows: `%APPDATA%\Inset Shelf`

### Getting started

The app teaches itself in the shelf, on macOS and Windows:

- **Getting started** is a short checklist at the top of the list, such as "Getting started · 2 of 5". It covers saving selected text with double Shift, capturing part of the screen, pinning a spot or drawing a sketch, linking a window, and checking off or copying an item back.
  - Each task ticks itself off when you really do it, not when you click it. Clicking a task shows how, beside the control to use.
  - The chevron folds the list, and **×** closes it. Once every task is done it says so once, then goes.
  - **Help > Getting Started** brings it back, as does the menu bar icon's menu. On Windows it is in the shelf's **⋯** menu and the notification area icon's menu.
- **Tips**: the first time you meet a few controls, a small bubble beside them says what they do. That happens on the window-link picker, a screenshot card, a new drawing and the **Add** menu in details. Only one tip shows at a time, and never over an open menu. `Esc`, a click elsewhere or using the control puts it away, and it never comes back.
- **Show Me Around** (**Help > Show Me Around**, the menu bar icon's menu, or **Done** in the setup window) dims the shelf except for one control at a time, with a bubble saying what it does. It goes through the list, an item's source line, the note field, the **+** menu, checking off and copying, and the **⋯** menu. `→`, `←`, `Return` and `Esc` move through it.
- **Examples**: the very first run puts four example items on the shelf, each tagged **Example** and each a thing to try. They behave like any item, so checking one off or copying it ticks the checklist too.
  - **Remove Examples** in the checklist's **⋯** menu deletes them. They are never added again.
  - **Copy as List** of a section's open items leaves them out.
- **Settings > Tips** turns the tips off, and **Reset Tutorial** starts the checklist and the tips over. The examples are not added again.
- An install that ran before the tutorial existed gets the checklist and tips, but no examples. With **Reduce motion** on, bubbles and the walkthrough appear without animation.

### Things to know about double Shift

- The app copies your selection by sending `⌘C` (`Ctrl+Insert` on Windows) to the app in front, then puts the clipboard back. Clipboard history tools may still record that copy.
- An app that ignores `Ctrl+Insert` copies nothing, so double Shift only shows or hides the shelf there.
- In VS Code, Cursor and some other editors, copying with nothing selected copies the whole line. Double Shift then saves that line instead of showing the shelf.
- Double Shift inside the shelf only hides it, so the shelf never saves its own text.

| Command | What it does |
| --- | --- |
| `pnpm check` | Runs Ultracite: Oxlint with type-aware rules and the React, TanStack, Vitest, shadcn and anti-slop presets, plus an Oxfmt format check. |
| `pnpm typecheck` | Type-checks the main, preload and renderer code in strict mode. |
| `pnpm test` | Runs the Vitest suite. |
| `pnpm build` | Builds the app into `out/` with electron-vite. |
| `pnpm fix` | Formats the code and applies safe lint fixes. |
| `pnpm screens` | Builds, then renders the shelf, the window-link picker, the drawing window, the setup window and the tutorial's checklist, tips and walkthrough in their main states, light and dark, in Playwright's Chromium with a fake preload bridge and sample data. Writes PNGs to `release/screens/` and fails a scene that overflows at 360×620 or whose check fails (the `#` section, layered `Esc`, `⌘Z` after removing a step). `SCREENS=details` renders only the scenes with that word in their name. |

To build installers on your machine, run `pnpm package:mac` on macOS or `pnpm package:win` on Windows. The files land in `release/`.

### Verify on the real macOS desktop

`scripts/e2e/verify-macos.ts` drives the real app from outside with real Shift taps, clicks and drags, and with the real clipboard. It opens its own small text app as "the app in front" and sends keys only while that app is in front.

```sh
node scripts/e2e/verify-macos.ts dev       # builds, then tests out/ with Electron
pnpm package:dir && node scripts/e2e/verify-macos.ts packaged
node scripts/e2e/verify-macos.ts dev say-why   # only the why field: 20 trials, Esc, unused, hidden app, full screen
node scripts/e2e/verify-macos.ts dev recall    # only recall, on a seeded shelf, then again with recall off
```

The script takes over the mouse and keyboard for about three minutes and overwrites the clipboard. At the end it puts back plain text it found there, but not images or files. The terminal needs **Accessibility** access, Xcode command line tools must be installed for `swiftc`, and the app under test needs **Screen & System Audio Recording** access. It writes every result and the event log to a temporary folder and prints the path.

## Release

`.github/workflows/release.yml` publishes builds to GitHub Releases.

A push to `main` updates the **Preview build** prerelease in place, and installed apps update from it. Each preview build gets the version `<major>.<minor>.<run number>`: the major and minor numbers come from `version` in `package.json`, the last number from the workflow's run number, so every build is newer than the one before. The new files are uploaded first, then `latest-mac.yml` and `latest.yml`, which tell the apps what is new. The update files the previous `latest*.yml` named stay for one more build, so an app that read it just before the switch can still download them. Older files are removed.

To cut a versioned release, set `version` in `package.json` (for example `0.2.0`), merge it to `main`, then push a matching tag: `git tag v0.2.0 && git push origin v0.2.0`. The tag build keeps that version as it is and publishes a separate release. Raising the minor or major number also moves the preview builds that follow to `0.2.<run number>`.

The macOS job signs with the shared certificate from the `MAC_SIGNING_P12_BASE64` and `MAC_SIGNING_P12_PASSWORD` secrets, through `scripts/import-signing-key.sh` and the `scripts/sign-mac.ts` hook, and fails without them. The CI workflow has no secrets and signs ad hoc. A local `pnpm package:mac` signs with the certificate when its keychain (`~/Library/Keychains/inset-signing.keychain-db`) is on the machine, and ad hoc otherwise.
